# Architecture Review
Generated: 2026-08-27T20:19:50.176Z

## Summary
The codebase has a clean domain/storage/state/components layering with good use of discriminated-union results and defensive SDK wrapping, but several cross-cutting patterns were duplicated ad hoc instead of centralized, which has already caused a real data-inconsistency bug in relation/event labels. A purpose-built shared layout component (AppLayout) sits unused while its logic is re-implemented three times, and a handful of exports/files are dead weight.

## Issues
### Critical
- [duplication] EVENT_TYPE_LABEL / RELATION_LABEL maps are independently redefined in 4+ files with drifted values for the same domain enum: CLOSE_FRIEND renders as '절친' in the input form but '친한 친구' everywhere it's displayed (history list/detail, share card); OPENING renders as '개업' in some places and '개업식' in others. — Files: src/components/CalculateForm.tsx, src/pages/History.tsx, src/pages/HistoryDetail.tsx, src/pages/Stats.tsx, src/components/shareCardRenderer.ts / Fix: Extract a single src/domain/labels.ts (or src/lib/labels.ts) exporting EVENT_TYPE_LABEL and RELATION_LABEL keyed off EventType/Relation, and import it everywhere instead of redeclaring local copies.
