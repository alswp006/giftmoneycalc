# Architecture Review
Generated: 2026-08-29T17:14:53.490Z
Score: 80/100

## Summary
This is a small, well-organized React app (components/lib/pages/types split) with no circular dependencies and generally consistent naming conventions. The main weaknesses are a few duplicated/inconsistent patterns around localStorage JSON parsing and label lookup, some stringly-typed domain fields that push validation to runtime instead of compile time, and a couple of small dead-code exports.

## Issues
### Warnings
- [consistency] Domain fields (eventType, relation, region, attendance, venue) on CalcInput are typed as raw `string` even though each has a fixed, enumerable set of valid values (BASE_TABLE keys, REGION_OPTIONS, ATTENDANCE_OPTIONS). This forces defensive runtime normalization/guards (normalizeCalcInput, safeCalculate returning null on unknown combos) instead of catching invalid values at compile time. — Files: src/types/calc.ts, src/lib/constants.ts, src/lib/calc.ts / Fix: Derive literal union types from the existing data (e.g. `type EventType = keyof typeof BASE_TABLE`) and use them in CalcInput so invalid strings are caught by the type checker.
- [structure] BASE_TABLE (lib/constants.ts) and EVENT_LABELS/RELATION_LABELS (lib/labels.ts) both hard-code the same set of eventType/relation string keys independently, with no shared type linking them. Adding a new event type to one map but forgetting the other silently degrades (falls back to '기타 경조사'/'지인') instead of failing loudly. — Files: src/lib/constants.ts, src/lib/labels.ts / Fix: Introduce a shared EventType/Relation union (or a single source-of-truth config object combining amount + label) and have both BASE_TABLE and the label maps reference it so mismatches are caught by TypeScript.
- [duplication] Safe JSON-parsing-from-localStorage logic is implemented twice with slightly different shapes: getHistoryList() in lib/storage.ts (try/catch + Array.isArray + per-field validation) and readDraft() in pages/Home.tsx (try/catch + typeof object check + normalizeCalcInput). Both exist to solve the same 'don't let corrupted storage crash the UI' problem. — Files: src/lib/storage.ts, src/pages/Home.tsx / Fix: Extract a generic `getJSON<T>(key, validate): T | null` helper into lib/storage.ts and have both getHistoryList and readDraft call it, keeping storage-parsing logic in one place.
- [consistency] Two different patterns are used for the same 'value -> display label' concern: eventLabel/relationLabel in lib/labels.ts do a Record lookup with fallback, while attendanceLabel in pages/ResultPage.tsx does an Array.find over ATTENDANCE_OPTIONS with a fallback. This inconsistency makes it unclear which pattern to follow when adding new label lookups. — Files: src/pages/ResultPage.tsx, src/lib/labels.ts / Fix: Move attendanceLabel into lib/labels.ts and implement it with the same Record-lookup style as eventLabel/relationLabel (or convert ATTENDANCE_OPTIONS lookups everywhere to a single shared `optionLabel(options, value, fallback)` utility).
- [dead_code] ButtonStack is exported from src/components/BottomCTA.tsx but is not imported or rendered anywhere in the codebase (only SubmitFooter is used, by AppErrorBoundary, HistoryPage, and ResultPage). — Files: src/components/BottomCTA.tsx / Fix: Remove ButtonStack if it's not needed, or wire it up where a primary+secondary CTA pair is actually required; otherwise it's untested, unused surface area.

### Suggestions
- [structure] Storage keys are declared in inconsistent locations: HISTORY_STORAGE_KEY lives in lib/storage.ts, but DRAFT_STORAGE_KEY is declared locally inside pages/Home.tsx even though it's used with the same getItem/setItem helpers. — Files: src/pages/Home.tsx, src/lib/storage.ts / Fix: Move DRAFT_STORAGE_KEY next to HISTORY_STORAGE_KEY in lib/storage.ts so all localStorage keys are discoverable and collision-checked in one file.
- [dead_code] snapToLadder is exported from src/lib/calc.ts but has no callers anywhere; safeCalculate uses the internal (non-exported) snapToLadderIndex directly instead. — Files: src/lib/calc.ts / Fix: Remove the exported snapToLadder wrapper if no external caller needs it, or if it's meant as a public utility, add a usage/test to justify keeping it exported.
- [naming] Page component naming is inconsistent: Home.tsx omits the 'Page' suffix while ResultPage.tsx and HistoryPage.tsx include it, even though all three are routed top-level pages in src/pages. — Files: src/pages/Home.tsx, src/pages/ResultPage.tsx, src/pages/HistoryPage.tsx / Fix: Rename Home.tsx to HomePage.tsx (and the default export to HomePage) to match the established `*Page` convention, or drop the suffix from the other two for consistency.
