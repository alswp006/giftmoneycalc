## Summary
The codebase is a well-organized React/TypeScript Toss mini-app with clean layering (components/hooks/lib/pages), a consistent Result<T> error-handling pattern in the storage layer, and good use of shared primitives (ScreenScaffold, Card, NAV_TABS). The main weaknesses are copy-pasted logic that has already started to drift (haptics, relationship/event labels), a stale 'contract.ts' whose type names collide with the real domain types but describe a different, unimplemented data model, and a couple of components/utilities that are dead code. No circular dependencies were found.

## Issues
### Critical
- [dead_code] lib/contract.ts declares an entire parallel type system (AppErrorCode, RouteState, Settings, DomainRecord, calculateFn, subscribeRecordsFn, useAdConfigFn, etc.) whose names collide with real exports in lib/types.ts but describe completely different, unimplemented shapes (e.g. contract's AppErrorCode is a string enum like 'NOT_FOUND', while the real one in types.ts is numeric like 404; contract's calculateFn takes `amountKrw`, while the real `calculate` in lib/calc.ts takes a CalcInput). Almost none of these types are imported anywhere in the app. — Files: src/lib/contract.ts, src/lib/types.ts / Fix: Delete lib/contract.ts (or clearly mark it archival/non-authoritative) now that implementation has diverged — keeping same-named types with different shapes around is a landmine for future edits/imports.
